# CrossWeave 보안 모델과 연구 근거

독립 검토 전 보안 강도는 **미확정**이다. 기능 시험 통과는 안전성 승인이 아니다.
증명, 작은 영역 전수 검사, 실제 공격, 표본 관측, 미해결 한계를 구분한다.
탐색 실패나 시간 초과를 공격 부재의 증명으로 표시하지 않는다.

공개 순열 질의 수 q, 전체 처리 블록 sigma, 위조 시도 v, 사용자 수 u를
따로 기록한다. 이상적인 단일 순열 sponge의 birthday 척도 `q^2/2^256`은
현재 keyed 모드와 공통-prefix P12/P16에 대한 보안 상한식이 아니다.
균일 독립 태그 추측의 `v/2^128`도 CrossWeave에서 성립한다고 검증하지 않았다.
전체 라운드 차분·선형·적분·불변 부분공간 분석과 AEAD 위조 분석은 미완료다.

공개 순열 구별자는 필요한 키·Nonce·오라클 조건을 연결하기 전에는 AEAD
위조로 간주하지 않는다. 실제 공격 보고에는 성공 조건·질의·시간·메모리·데이터·
시드·검증 대상 지문·정확한 시작 라운드를 포함한다.

## 키 재사용과 Nonce 중복

같은 키의 암호화 Nonce는 고유해야 한다. 독립 균일 난수 n개의 128비트
Nonce 충돌 확률은 대략 `n*(n-1)/2^129`다. 카운터라면 재시작·동시 실행·
롤백에도 중복을 막아야 한다. 라이브러리의 바이트 길이 검사로 고유성을
보장할 수는 없다. 다중 사용자·키당 사용량은 별도 분석 대상이다.

동일 `(key,nonce,AD)`의 첫 rate 상태 Z에 대해 `C=P XOR Z`,
`C'=P' XOR Z`이므로 `P'=C XOR C' XOR P`다. 알려진 평문 한 쌍으로
다른 평문의 공통 첫 최대 16바이트를 복구한다. 이후 블록 복구나 태그 위조까지
주장하지 않는다. 현재는 모드 수식의 대수적 결과이며 실행 AEAD 회귀는 후속
구현에서 검증한다. misuse resistance·관련 키 안전성·forward secrecy는 미보장이다.

## 기존 구성과의 비교

NIST SP 800-232 §§3~4, Algorithm 3 및 duplex 원문 §§2~4와 비교했다.
구조 유사성이나 크기 차이는 CrossWeave의 안전성·독창성 증명이 아니다.

| 항목 | CrossWeave | Ascon-AEAD128 |
|---|---|---|
| 상태 / rate / capacity | 384 / 128 / 256비트 | 320 / 128 / 192비트 |
| 키 / Nonce / 태그 | 각각 128비트 | 각각 128비트 |
| 비선형층 | 이웃 레인 회전·AND·덧셈의 XOR 갱신 | 5비트 S-box와 레인별 선형 확산 |
| 호출 | 공통 prefix의 앞 12/16라운드 | Ascon-p[8]/p[12] |
| 초기 배치 | nonce, key, 128비트 IV | 64비트 IV, key, nonce |
| 빈 AD | 패딩과 최종 AD 마커 처리 | AD 블록 처리 생략 |
| 도메인 분리 | AD/메시지 완전·최종 및 최종화의 5개 마커 | AD 뒤 도메인 분리 비트 |
| 최종화 | capacity key XOR, 마커, P16, rate XOR key | 별도 key 주입, p[12], 태그 추출 |

공개 순열·rate에서의 평문 XOR/암호문 덮어쓰기·초기화/최종화 key 주입은
duplex 계열의 공유 구조다. 상태 폭과 라운드 수 변경으로 기존 정리가
이전되지는 않는다. 현재의 키 주입·패딩·공통-prefix 호출을 포함하는 별도
보안 증명이 필요하다. 회전/레인 재명명에 대한 완전한 동치 판정은 미실시다.

출처: [NIST SP 800-232](https://doi.org/10.6028/NIST.SP.800-232),
[Duplexing the sponge](https://keccak.team/files/SpongeDuplex.pdf).

## 초기 구조 공격 검사

실행: `make research`. 전체 관측·입출력 증거·소스/명세/KAT SHA-256은
[`early_gate.json`](early_gate.json)에 기록했다. 시드는
`0x63726f7373776561`, 기본 코어는 GCC 13.3.0, C11, `-O2`로 빌드했다.
공격자에게 키 없는 전체 상태 및 축소 라운드 정방향 질의를 허용한다.

### 수식으로 확인한 한 라운드 구별자

입력 차분이 `Δa=(α,0,0,0,0,0)`, `α!=0`이면 짝수 갱신의 f 입력이
같으므로 갱신 뒤에도 짝수 차분은 `(α,0,0)`이다. 홀수 레인 3은 레인 2/4만
읽으므로 그 차분은 0이다. 라운드 상수는 XOR 차분에서 상쇄된다. 재배열 뒤
출력 차분 d는 **항상 `d[0]=d[3]=d[5]=0`, `d[4]=ROL64(α,43)`**다.
나머지 두 레인만 자유롭다. 이 조건은 임의의 전체 입력, 시작 라운드 0~15에서
성립한다. 16개 시작점 × 4개 α × 32개 상태 = 2,048쌍으로 재현했다.

한 라운드 순열을 독립 무작위 384비트 순열과 구별하는 데 질의 2회가 든다.
무작위 순열의 서로 다른 두 출력 차분이 이 조건을 만족할 확률은
`2^128/(2^384-1)`이다. 계산·데이터·추가 메모리는 상수 크기다.
이는 **실제 한 라운드 구별자**이며 P12/P16 또는 keyed AEAD 공격이 아니다.
첫 라운드의 제한된 의존성에 관한 결과라 전체 강도를 이 확률로 해석하지 않는다.

### 한정된 표본 탐색

모두 시작 라운드 0 기준이다. 고정점·길이 2 이하 순환은 구조 입력 391개와
난수 상태 1,024개를 라운드 수 1/2/3/4/12/16마다 검사했고 발견은 0이었다.
모든 레인 동시 비트회전 63종, 순환 레인 이동 5종, 전체 보수 1종에 대해
`P(T(x))=T(P(x))`를 라운드 수 1/2/4/12/16, 변환당 128상태에서 검사했고
일치 0이었다. 이는 임의의 대칭·불변 부분공간을 전수 조사한 것이 아니다.

모든 단일 비트 입력 차분 384개에 각각 16쌍을 적용했다.

| 라운드 수 | 출력 차분 Hamming 최소 / 최대 / 평균 | 같은 입력 차분의 최다 동일 출력 / 16 |
|---|---|---|
| 1 | 4 / 67 / 17.379883 | 7 |
| 2 | 32 / 207 / 122.725423 | 1 |
| 3 | 140 / 228 / 189.143229 | 1 |
| 4 | 155 / 232 / 192.107585 | 1 |
| 12 | 158 / 224 / 192.019531 | 1 |
| 16 | 155 / 224 / 192.044434 | 1 |

이는 확산 관측이며 trail 확률 상한·선형 편향·안전 라운드 수의 근거가 아니다.
최소 사례의 전체 입력과 차분은 보고서에 남겼다. 12/16라운드에서 이 탐색이
검사한 고정점·짧은 순환·단순 대칭·반복 차분 후보는 관측되지 않았다.
미관측은 공격 부재를 증명하지 않는다. 다중 비트 차분, SAT/MILP 경로,
선형 hull, 적분·zero-sum·대수차수·불변 부분공간·키드 모드 연결은 미해결이다.

전체 실험은 중복 포함 순열 질의 101,300회, native 프로세스 2,752개였다.
기록 실행 wall time은 2.827168초, Python 및 최대 child RSS는 각각
12,544KiB였다. RSS는 프로세스 high-water 관측이고 증명된 공간 상한이 아니다.
다른 환경의 시간·RSS는 바뀐다. 재현 검사는 관측과 대상 지문을 비교하며
시간·RSS·OS 문자열 일치를 요구하지 않는다.
